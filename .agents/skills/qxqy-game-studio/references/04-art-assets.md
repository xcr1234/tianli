# 4. 准备千星美术参考图和素材

## 输入与适用时机

读取已经确认的 HTML 效果、策划案中的美术意图和用户提供的参考。正式素材准备位于 HTML 体验确认之后，步骤 4 不打开模拟器或修改存档。

## 执行动作

在 `docs/art-bible.md` 记录体验形容词、主/辅/警示色、轮廓、UI 层级、角色/道具识别特征、素材来源与用途、目标官方 `imageId` 和模拟器占位。准备参考图、素材清单与千星控件还原方案。

有真正视觉分歧时，在同一布局和玩法状态下提供少量可比较方向，请用户选择；没有分歧则采用推荐方向。按当前工作区和会话实际可用能力，使用像素画、图元拟合、UI 制作或帧动画 Skill。

官方原神/千星素材可以使用。模拟器对 `100001–100006` 使用基础图元代理，另支持固定白名单静态图片的按需下载与本地缓存；白名单外或加载失败仍显示缺失框，截图可通过 `assetWarnings` 区分下载失败。记录真实目标 ID，九宫格/动效及实际视觉仍留待真机核验。高成本拼图或帧动画先准备关键样本，批量制作随步骤 5 的实现需要推进。

### 图片拟合方式

需要图元拟合时，先读取项目 [图片拟合指南](../../../../docs/image-fitting.md)。其中维护在线入口、Git 源码部署命令、参数和交付要求：

- 方案一：读取项目内 [miliastra-image-css-builder](../../miliastra-image-css-builder/SKILL.md) 生成可导入 CSS，或按已核验的场景结构准备 JSON，在 [图片编辑器](https://qx.070077.xyz/) 中检查、精修和导出；适合简单图标、UI 拼接与局部调整。Skill 及参考已随模板安装，但网站服务和页面 WebMCP 是否可调用仍需实际核验。
- 方案二：用 [图片图元拟合工具](https://qx-img.070077.xyz/) 自动拟合现有图片并导出；复杂参考图默认先走此方案，再按需将场景 JSON 导入方案一编辑器精修。
- 在线不可用时，可克隆两个对应 GitHub 仓库在项目 `.local-tools/` 本地启动，使用工具目录内虚拟环境和依赖；不能把网站暂不可用直接视为整个素材步骤阻塞。需要补齐实际缺少的运行环境时说明缺项，不安装到全局。
- 在 `docs/art-bible.md` 记录素材来源、实际版本、预算、尺寸、透明背景、参数、预览和 JSON。比较效果时统一图元预算与目标显示尺寸，选择建议不当作已完成的实测排名。
- 本步骤保存参考与可编辑素材。后续在步骤 5 把外部绘图 Lua 整理成模块，由主入口调用，再打包交付；不直接拼接多个 `OnStart`/`OnDestroy`。

### UI 还原规格

布局字段使用千星坐标：原点左下、Y 向上，锚点取值 0–1；不写 DOM 选择器、CSS 类或 JS/Lua 函数名。

| 字段 | 含义 |
|---|---|
| `id` / `kind` | 稳定控件名与 `container/image/text/button/progress` 等目标类型 |
| `parent` / `anchor` / `offset` / `size` | 控件树与跨画布布局 |
| `styleToken` / `assetId` | 色板、字号、间距与资产清单引用 |
| `visibleWhen` / `action` | 可见状态与抽象玩家动作 |
| `motionIntent` | 触发、时长、曲线和可降级方式 |

还原方式优先落到 Lua 实例化基础模板并配置属性，详见 [步骤 5](05-lua-implementation.md#接入模拟器与搭建骨架)。HTML（若存在）与 Lua 可以有不同适配层；稳定的状态、动作、控件和资产 id 必须可追踪。网页坐标不得进入 Lua。
